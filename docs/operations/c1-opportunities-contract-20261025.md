## Remaining original server-only target conflict

This completes the shared consumed join; it does not claim the final view is
produced solely by the earlier account HTTP response. That response precedes
independent broad-screen/holding-quote observations and does not contain the
browser's retained verified selection. The same response can therefore correctly
render different actions when a later verified holding quote breaches a stop,
an independently observed event changes selection, or a failed refresh retains
the prior source. Existing golden fixtures exercise these differences while the
complete supplied account/opening response remains unchanged.

Forcing those later observations into that earlier response would require an
additional round trip, a changed request order, or substituting a different
observation. None preserves the existing timing/input invariant by construction.
No new request or replacement observation is added. The finite checklist must
retain this exact literal server-only boundary as unmet if that acceptance
criterion is required; a shared consumed contract is not evidence that the
server saw the owner's browser or reconciled a brokerage account.
