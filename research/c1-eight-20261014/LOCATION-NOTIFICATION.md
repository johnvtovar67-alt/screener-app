## What the current primary source requires

The [current FMP Terms of Service](https://site.financialmodelingprep.com/terms-of-service), page marked **last updated August 1, 2023**, state in §2.8:

Section 2.8 requires the customer to notify FMP of location IP/domain aliases whenever data is stored or processed there.

This is a notification requirement. Section 2.8 does not expressly prescribe prior approval, acknowledgement, a deadline or a notification form. Its other provisions concern storage security, access by the customer/authorized agents/FMP, and audit rights.

Ordinary reading includes temporary RAM-only calculation: processing is separately covered even when source inputs are never saved. No personal, small-sample, temporary, RAM-only or cloud exemption appears in the reviewed terms. Section 1.1 subjects use to these terms and applicable Order Forms; §§14.2/14.4 require written signed waivers/amendments. The reviewed receipt proves a paid subscription, not a negotiated exception. The user's separate pause controls the present workflow regardless of §2.8's unspecified timing.

## Public clarification does not remove the requirement

[FMP's September 17, 2026 private-research/publication guidance](https://site.financialmodelingprep.com/insights/platform/can-you-publish-fmpsourced-charts-tables-or-research-in-a-newsletter) supports the individual holder's personal, non-business notebook or spreadsheet, subject to the plan and terms. It does not address or waive processing-location notification. It distinguishes private personal research from reports or derived displays reaching another person.

The [current FMP FAQ](https://site.financialmodelingprep.com/faqs?code=platform), with no visible publication/update date, says its API is compatible with OpenAI and directs users to support for further information. Technical compatibility does not establish a license exception for Codex Cloud. No primary-source clarification exempting ephemeral personal cloud processing was found in the targeted review. The terms-linked Acceptable Data Use Policy remained unavailable in the earlier permissions review; no extra rights are inferred from its absence.

## Information for FMP

The express §2.8 notification content is the **IP and domain aliases of every location that stores or processes the data**. For this proposed workflow, describe the following so FMP can identify the locations and resolve cloud-specific ambiguity:

1. Account identity and current Ultimate personal subscription. Send from the account email; do not send an API key, password, payment data or licensed price sample.
2. The processing provider/service: the existing OpenAI Codex Cloud execution environment, used only for the account holder's private, non-business research. Identify the actual external egress IP address(es) or provider-confirmed range and relevant processing-domain aliases. If these rotate or are not available, explicitly say so and ask what cloud identifier/range or registration procedure FMP accepts.
3. Any verified processing/storage region and separate storage location/domain for owner-private aggregate reports, including any later personal-device download. Geographic region is useful identification; §2.8 itself expressly names IP/domain aliases rather than listing a required country field.
4. Handling: raw/normalized inputs only in temporary process memory; no source inputs in logs, model context, Git, source-price tables or public artifacts. Only owner-private aggregate summaries are saved. Public checkpoint contains code and non-price audit only. Describe access/deletion controls accurately; do not certify unverified platform controls.
5. Request confirmation that this information satisfies §2.8 for this environment, how to handle changing cloud IPs, whether the proposed third-party processing/private aggregate retention requires additional consent under the personal license, and any required update/deletion procedure.

The additional workflow details in items 1–5 make the notification actionable; they are not represented as an exhaustive contractual form mandated by §2.8. A request for written clarification is distinct from claiming §2.8 itself requires prior approval. Any broader personal-license, third-party-use or retained-output authorization remains a separate question.
