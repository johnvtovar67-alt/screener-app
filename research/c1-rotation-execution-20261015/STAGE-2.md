# Approved acquisition tranche 2

This tranche has a hard maximum of **250 additional FMP requests and 20 MiB
(20,971,520 decompressed response-body bytes)**. Both successful and error bodies
count. Requests are sequential, starts at least two seconds apart, with no
retries. Any provider limit, authentication/HTTP/transport error or private
preservation failure stops acquisition. One security with a data-validation
failure is isolated and its remaining views skipped; a second failed security
stops the tranche. No provider error is treated as an isolated data gap.

The owner authorizes this measured tranche without another dashboard check or
infrastructure project. Remaining account-wide quota is unknown. The rate and
stop policy conservatively limit this research job's load; they cannot establish
the remaining bandwidth available to production or exclude other key users.

## Recovery gate

Before FMP acquisition, a new verifier agent with no parent conversation history
fetched committed recovery code and retrieved the prior stage's private evidence,
journal and all 25 response objects into a newly created empty directory. It did
not read existing local licensed-input directories. Recorded byte counts and
hashes, evidence inventory and code provenance were checked. The full receipt
and normalized acquisition-gate receipt remain private.

This is a fresh Codex agent context and clean-directory recovery in the existing
managed environment. It is **not a separately provisioned cloud session or
machine**. Durable private objects, existing configured access and the recovery
instructions—not a local cache—supply the inputs. No original archive was listed
or accessed. A failed recovery gate prohibits substantial accumulation.

## Preservation and completion

The client stores the manifest and recovery receipt privately before its first
FMP call. Each response and immutable progress-journal checkpoint is uploaded
before another FMP request. The final sealed journal, coverage/validation audit,
source hashes and completion receipt are private. A clean process must retrieve
the completed tranche and verify every response. Licensed rows, record hashes,
private addresses, detailed unit diagnostics and numerical portfolio outputs do
not belong in Git. Public operational counts and nonproprietary code may be
checkpointed.

505 constituent lines plus the two benchmarks. Exactly **423 lines /1,269
three-view price requests** would remain, before action, identity and additional
consistency work. Actual failures/cap stops must replace that conditional count
in the completion report. Unused calls do not authorize another acquisition
manifest. The cumulative experiment request/byte ceiling remains controlling.

sleeves, sizing, costs, risk controls and accounting contract remain unchanged.
