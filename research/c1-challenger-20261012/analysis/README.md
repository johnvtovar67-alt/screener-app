# Offline scorecards and locked validation

These tools prepare the still-open Challenger research. They do not execute a strategy, acquire market data, modify application imports, or certify historical alpha. No historical Challenger result or finalist has been generated. The production-equivalent baseline uses engineering commit `e2b98471311fb702113baf0ca64473b92ccfd142`, with SCHW excluded from allocation and retained in holding ranks. The historical audit baseline uses `006e067697385143684c7417b18bc7909c2d217e`. Its saved 289.07% result remains separate.

Run software checks from the repository root:

```sh
node research/c1-challenger-20261012/analysis/diagnostics-regression.cjs
```

The 28 checks use explicitly synthetic account curves and ledgers. They verify partial-sale cashflows, exact marked P&L attribution, overlapping issuer episodes, winner-removal drawdowns, carried-state period boundaries, first validation returns, zero denominators, prior-session regimes and overlapping flags, missing calendar windows, private output confinement, public redaction, full rejection ledgers, finalist limits, input-transform receipts, and the original/amended plateau rule. They do not provide comparative historical evidence, a GitHub lock, licensed data access, or source-baseline performance verification.

`scorecard.cjs` inherits primary full-period metrics unchanged from the preserved replay's `calculateMetrics`. Its supplemental calculations use the source replay's complete `curve`, `trades`, `fills`, and `accountTrace`. In particular:

- The primary source ledger supplies completed sleeve round-trip statistics and exact two-way turnover. Actual modeled-fill notional is a separate diagnostic, with its difference from source ledger notional shown explicitly.
- Validation uses the previous development close as its equity and benchmark anchor. The first validation return is included, and cash, shares and counters remain on the continuous source path. Period turnover and utilization exclude the extra anchor from observation denominators; completed trades are attributed by exit date, including carried entries.
- Supplemental QQQ comparisons show relative-wealth growth/drawdown, CAGR difference, daily active-return tracking error/information ratio, full-window beta/correlation and annualized mean beta residual. The descriptive zero-risk-free fit is calculated after permitted period exposure; it is never a trading input or certified alpha.
- CAGR uses actual elapsed calendar time. Supplementary Calmar, expectancy, net P&L per traded/invested dollar, invested-normalized concentration, effective issuer count and risk measures explicitly preserve undefined denominators. The source's inherited zero-return conventions remain unchanged and are accompanied by statistical-availability annotations.
- Sleeve contribution paths equal cumulative net trade cashflows plus exact actual-book shares marked at the source state's closing `lastPrice`. Completed paths must reconcile with source `roundTripPnl`. Fees are included when present; the pinned model uses zero commission and adverse cost-adjusted fill prices. Partial sales and completion purchases remain in their position ID. Issuer episodes merge overlapping sleeve ownership and same-session reentry, because source close-level ordering cannot prove intraday separation.
- Top 1/5/10 winners are selected ex post, and their cumulative marked P&L is subtracted at every close while all later fills, quantities and decisions remain fixed. Final subtraction is independently checked. The resulting residual drawdown is an explanatory contribution stress, never an investable no-winner counterfactual. Open terminal positions are reported separately.
- SPY regime flags use only observations through the preceding completed session. Exact original SPY warmup/history must be supplied; missing history stays unavailable. Each prior 21/50/64/200/252-close window requires positive finite observations; missing, undefined, nonfinite or nonpositive observations yield unknown (`null`) labels, with no filling. Recovery also requires its 252-close drawdown window. Unaffected shorter windows can remain observable. SPY observations during each analyzed period must exactly match source benchmark closes. Flags overlap, and overlap counts remain explicit. Full, development and validation regimes are separated; validation is anchored at the prior close and comparison uses validation regimes, so development cannot hide later deterioration. Per-regime attribution is compounded over labeled returns, while local drawdowns use contiguous regime episodes.
- Post-exit opportunities require exact original unheld-symbol closes. The fixed explanatory horizons are 20, 60 and 120 source sessions, declared before historical Challenger comparisons. Constant final-sale proceeds are compared with future closes; replacements, financing and extra costs are not inferred. Missing marks stay unavailable. Peak-to-exit giveback retains the source MFE statistic and a separately labeled net exit return.

`developmentCard` truncates every source array at the last existing session on or before December 31, 2024 before calculating supplemental statistics. It removes full-period metrics, final state and simulator traces. It never returns validation, later calendar windows, or post-development opportunity marks. `scorecard` on a full run exposes later performance and is reserved for the separate historical audit baseline or post-lock validation. The CLI enforces that ordering; direct module consumers must preserve it.

Public exports use allowlists. They contain aggregate statistics, permitted period summaries, hashes and source identities. They exclude daily return arrays, prices, positions, raw ledgers, trade/issuer identities, contribution paths, residual curves, and symbol-level post-exit observations. Raw/private outputs must be written outside this public repository. `--private-root` must be an existing directory; each referenced private file and output parent directory must already exist under it. Existing and dangling symlinks are rejected with `lstat`; outputs use exclusive creation (`wx`) and require new versioned filenames. Symlink escapes and overwrite races are rejected. This filesystem guard supplements the separate licensing, exact-input and durable-private-storage gates; it does not certify them.

The CLI requires explicit replay metadata and G0–G4 passing receipt hashes for Challenger analysis. Every raw replay analysis also requires `researchIdentity.privateChronologicalVerificationPassed: true` and a private complete chronological receipt whose `passed`, `effectiveSourceIdentityMatches`, `sourceGraphMatches`, `inputContentMatches`, and `inputManifestMatches` are all true; generic G3 evidence alone cannot bless an unverified run. The `baseline` stage requires G0/G1/G3/G4, because it produces the first source-specific evidence for G2, plus private complete chronological verification. It accepts only Champion at independently replayed 12/25/50 bps. Audit-baseline reproduction also requires a passing exact saved historical audit match. It emits only whole-period source metrics and supplemental QQQ-relative aggregates; no validation/calendar/year/regime slices are emitted. Both source identities remain separate. Set `researchIdentity.privateChronologicalVerificationPassed: true` only after the independent recorded replay passes; audit additionally needs `historicalAuditMatch: true` or `{passed:true}`. Conditional non-alpha/live-input rejection remains mandatory. Metadata supplied by the source-specific runner is:

  baselineRole: 'production-equivalent', // or 'historical-audit'

  baseSourceGraphSha256: 'b1a5d79c017cb96ff55037029dd343d75d4826a8fd7ba341ad2d183dc8d1c5bf',

Intentional factor and causal regime sidecars may change the replay dataset digest. The original common base digest is retained separately from the derived digest. Only the preregistered `horizon`, `global_sector`, `slow_fast`, `scale_drawdown` and `scale_volatility` families may differ, and their `researchIdentity.inputTransform` must identify `family`, `baseInputContentSha256`, `derivedInputContentSha256`, `preservedOriginalPriceUniverseVerified: true` and a passing `receiptSha256` (the `receiptSHA` alias is accepted). Other families must use the unchanged base input. Finalist locks freeze every experiment's actual derived digest, so later costs/validation cannot silently rebuild its signals or substitute inputs.

Every one of the 48 Challengers must have a development card or an explicit unsuccessful record with status `blocked`, `unsupported` or `failed` and its reason. Before `validation` or `compare`, the lock must be pushed to GitHub. `--lock-commit` requires its exact 40-character commit, `--lock-path` its research file path, and `--lock-branch` the remote research branch. The verifier checks the expected GitHub repository, reads the presently advertised branch head, fetches it without checkout, verifies lock ancestry, and reads immutable lock/governance bytes from the commit. It does not push, merge, build or deploy. A local lock file or merely claiming a commit was pushed does not satisfy the gate. This managed environment prohibits Node subprocesses (`EPERM`), so the shell-backed verifier cannot execute here. Use `--lock-read-receipt` after the orchestrator actually reads the immutable lock and governance files through the GitHub connector. The receipt is a separately collected provenance observation, trusted like G0–G4 receipts, with independent Git blob verification; it is not a signed server attestation or an adversarial access-control mechanism. The diagnostic report defaults to A pending written evidence review and never authorizes production action.
